# 传感器建图先验与全局重定位优化

本轮重新开展用户授权的建图、算法修改和测试；没有续跑或改写上轮停止的 `full_slam_20261026` 数据。当前实验目录为 `tools/global_relocalization/data/optimization_20261026/`，Point-LIO 根因对照为 `data/mapping_diagnosis_20261026/`。这些数据目录被 Git 忽略，迁移时需单独复制。

## 验收口径

- 理想地图严格指标仍记录为三维位置误差 ≤0.10 m、完整姿态 SO(3) 误差 ≤2°。
- 自主地图的附加验收指标为三维位置误差 ≤0.15 m、完整姿态误差 ≤3°。
- 两种口径均单独记录开始事件锁存到定位输出 ≤1 s。该时间不含静置标定、旋转及赛前全局检索。
- 用户明确要求重定位赛前准备保持原地旋转，不允许增加平移探测来消除对称歧义。该约束不改变建图阶段沿原路线采集的流程。
- 正式批次必须全部完成，并且每一项同时满足选定精度和时间要求。拒绝、超时、基础设施异常、缺失有效真值和未完成试次均不能变成通过。
- 每批默认生成 120 个新位置及随机朝向，覆盖负 x 半场有完整支撑和原地整圈净空的平地、高台；距二维障碍及未知高程至少 0.5 m，距历史点及批内其他点至少 0.25 m。实际碰撞几何还会检查整圈扫掠体，排除台阶、非水平支撑、缺支撑和净空冲突。位置采样不读取算法结果。
- `--regression` 仅用于历史点回归，永远不能获得正式验收通过；`--resume` 只能继续同一份冻结输入，不能换算法、地图、参数或重采位置。

批测同时保留严格指标及放宽指标，不修改估计器的配准质量、歧义或三帧停车确认门限。

## 建图链修改

1. **瞬时扫描时间模型。** Gazebo 点云转换器用显式 `instantaneous_scan` 输出零逐点时间；Point-LIO 的 `preprocess.instantaneous_scan` 禁止把全零时间重新解释成按方位角扫描。真实雷达的 Point-LIO 默认仍保留逐点时间处理。
2. **滤波公式与内存。** 修复 ESEKF 大观测分支把量测方差乘入信息矩阵的问题，统一为标准的除方差形式；修复两个仅 `reserve`、随后用下标写入的临时 vector。
3. **时钟与输入历史。** 实测系统时钟相对单调时钟回退约 1.996 s。原 `rclcpp::Rate` 调度停顿会使仅容纳 5 条消息的 IMU 队列丢观测。循环改用 `WallRate`；IMU/LiDAR 默认历史深度分别为 2000/100，内部缓存有硬上限，溢出明确失败。CSV 记录实际回调缺口、处理时间、队列、状态与协方差摘要。
4. **发送端传输。** `start_simulation.bash` 也加载大点云 Fast DDS 配置，避免只给接收端配置较大共享内存。保留用户显式提供的配置。
5. **采集控制。** 站点停平移并按实际姿态累计一整圈，不能按命令发出时间认定转完。无实际转动或长时间里程计滞后会停车、报错。高程路线使用连续受限垂直速度；车轮跨越不同高度时不要求底盘下降到中心栅格的理想接触高度。
6. **二维观测。** SLAM 可选择 `registered_scan` 当帧云。累积的 `terrain_map_ext` 不能被当作同一时刻、同一射线原点的激光扫描。独立高度筛选与反射强度筛选相配套。
7. **图修正插值。** 插值对象为 `C(t)=T_graph_corrected(t)·inverse(T_graph_odometry(t))`，真实运动仍由三维里程计提供。允许图节点间隔较长，但要求原始里程计连续覆盖且相邻时间间隔 ≤0.25 s；不向图时间范围外外推。这样不会丢掉未新增二维节点的原地整圈点云。

Point-LIO 修改通过 `pointlio_patches/` 应用于隔离源码，记录基础版本、补丁及实际源码哈希；没有恢复或改写用户原本有删除状态的子模块工作树。

## 重定位修改

- Scan Context 缓存列范数、批量计算列点积；近并列情况用原标量计算复核，保持确定性选择。固定描述子微基准约提速 2.03 倍，不等于整轮定位提速两倍。
- 首批全部失败后补充有界候选。比赛配置检索前 40 个独立 XY 位置，补充候选全部验证后再做统一质量排序与歧义判断。
- 加入通用高度网格 `db_base_z_offsets: [0.0, 0.25, 0.5]`。候选预算按独立 XY 计数，选中位置的高度层共同参加配准，避免重复高度挤占位置覆盖。
- 保留 GICP 收敛、fitness、内点率、固定半场、歧义拒绝及三个不同时间戳的独立停车确认。
- 三帧停车配准用于验证整圈检索结果；确认通过后保留整圈点云求得的地图到参考帧变换，再合成输出时刻的局部运动。原先用最后一帧单视角配准覆盖整圈基准，可能使结果受最终朝向影响。相同 19 组可确认历史点云对照中，两种方法严格指标均为 17/19；自主地图指标由 18/19 变为 19/19，最大位置误差由 0.1566 m 变为 0.1266 m。个别点有取舍，例如一例由 0.0525 m 变为 0.1266 m；这些历史数据仅用于回归，不能代替新点验收。
- 原地旋转前端增加可选的底盘软平移先验，默认关闭，比赛旋转模式显式启用。残差包含雷达相对底盘的杆臂，不把雷达旋转位移误判为底盘平移；标准差由既有最大底盘速度和真实帧间隔决定，最小为 5 mm。点云仍估计完整六自由度，实际可观测的小平移仍可输出；过大真实运动、独立 LiDAR 可观测性和质量检查仍拒绝。
- 比赛局部对应范围由 0.5 m 收紧为 0.3 m，即当前 0.12 m 体素的 2.5 倍；fitness、内点率、运动及信息矩阵门限保持原值。对两例失败的消融表明：软平移先验解决虚假大平移，局部对应范围解决新增表面错误关联，两项组合才使两例全部已录帧通过。没有根据真值修改估计结果，也没有将真实位移硬设为零。

- 独立停车确认增加可选重力方向软约束，仅约束相对重力的两个倾斜自由度，不约束航向或 XYZ。输入必须是已由原始 IMU 对齐重力的参考帧，且 manifest 声明的地图竖直方向与配置一致，否则拒绝启动。比赛配置标准差为 0.005 rad；仅用于停车确认，整圈全局检索与最终输出基准不变，真实底盘滚转和俯仰仍通过局部运动合成保留。第 091 项的原确认扫描出现约 4.3–4.8° 假倾斜，而完整局部轨迹姿态误差不超过 0.215°；修复针对这一物理矛盾，没有放宽三帧确认门限。

参考了固定版本 z-localization 的 [Scan Context 实现](https://github.com/mozihe/z-localization/blob/76e126328b670adc92981d9b4900cc059a6f2343/src/backend/src/scan_context/descriptor.cpp)与[有界回退设计](https://github.com/mozihe/z-localization/blob/76e126328b670adc92981d9b4900cc059a6f2343/src/backend/src/relocalization_hypotheses.cpp)。

## 构建与复现入口

```bash
bash tools/global_relocalization/build.bash
bash tools/global_relocalization/build_full_slam.bash
source tools/global_relocalization/mapping_environment.bash

export ROS_DOMAIN_ID=82
export GZ_PARTITION=rm27_new_validation
bash tools/global_relocalization/start_simulation.bash gui:=false
```

另一终端加载同一环境和隔离域，使用全新输出目录：

```bash
python3 tools/global_relocalization/full_slam_mapping.py \
  --mapper "$PWD/tools/global_relocalization/.build/mapping_ros/install/point_lio/lib/point_lio/pointlio_mapping" \
  --control-source simulator --survey-terrain surveyed \
  --survey-waypoints tools/global_relocalization/config/survey_left_coverage.json \
  --speed 0.3 --max-wall-sec 2400 --output /data/new_capture
```

采集运行期间，在第三个终端加载相同环境后执行来源审计：

```bash
python3 tools/global_relocalization/audit_mapping_provenance.py \
  --domain 82 --require-mapping --output /data/new_capture/mapping_binary_provenance.json
```

来源审计必须在采集进程仍在运行时执行。采集完成后导出三维先验；源目录、二进制及冻结地图不可覆盖：

```bash
python3 tools/global_relocalization/export_raw_prior.py \
  --source /data/new_capture --output /data/new_prior

python3 tools/global_relocalization/sensor_map_batch.py \
  --node "$PWD/tools/global_relocalization/.build/ros/install/global_relocalization/lib/global_relocalization/global_relocalization_node" \
  --map-dir /data/new_prior --output /data/new_batch \
  --evaluation-profile sensor_map
```

未指定 `--trials` 时自动生成、冻结全新 120 点。默认历史排除覆盖本仓库 `data` 与 `config`；若外部保存试验，生成器需将其历史目录一并纳入，避免遗漏历史位置。三维原始先验的扫描默认链接到源采集，搬运时应同时保留源目录或使用硬链接/实体复制。
