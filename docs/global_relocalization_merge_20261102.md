# 全局重定位选择性合并验证（2026-11-02）

目标基线：`replace_gicp` / `735ef9a`。来源：`feat/global-relocalization` / `c9c7d75`。

## 合并范围

- 将完整全局定位包、action 接口迁至 `src/pnx-localization/`，保留 raw LiDAR/IMU 前端、检索、GICP、比赛状态机、停车确认及可视化。
- 保留 `competition.yaml`、参考 PCD、manifest 的原始内容；适配构建、测试和辅助工具中的新目录与包名。
- 迁移全局定位工具、先验构建与评估工具及其说明。`rm27_rendering` 仅供全局定位可视化辅助使用；既有仿真渲染入口继续采用目标分支实现。
- 在 `launch_bringup`、`rm_27_stimulation` 中接入出生选点、同时间戳位姿交接与导航启动协调。RViz 出生流程使用目标分支已有的凸包碰撞转换。
- `relocalization_manager` 的全局流程由 `wait_for_initial_pose` 开启。未开启时保留目标分支原来的运动判断、注册、连续修正与初始位姿处理。
- 独立演示生成的临时模型固定云台，兼容目标分支的活动云台和 IMU 插件；正式模型与导航物理控制保持目标版本。

没有从来源分支引入规划器、控制器、ROGMap、Point-LIO、loam_interface、sensor_scan_generation、点云转换器、导航 YAML、栅格地图、正式机器人 URDF、场地/碰撞网格或子模块指针的修改。其他导航开发和导航基准日志不在此次合并范围。

## 验证结果

| 检查 | 结果 |
|---|---|
| 全局定位及接口构建 | 2 个包通过 |
| 管理器、bringup、仿真与可视化辅助包构建 | 4 个包通过 |
| 全局定位 CTest | 8/8 组通过，包含 ROS action/比赛接口合约 |
| 工具、先验评估、station submaps、渲染辅助单元测试 | 182 项通过 |
| 全局交接、初始朝向、TF 所有者接线测试 | 21 项通过 |
| 管理器 CTest | 3/3 组通过；DDS 测试含全局交接、停车共识、倾斜拒绝与原连续定位模式，共 4 项 |
| 仿真 CTest | 11/11 组通过，包括 GT 时间戳交接和既有启动/物理组件测试 |
| 三组冻结地图查询，源版本与移植版本对比 | 两版本均成功；所有非耗时字段在 `1e-12` 容差内一致，最大数值差 `1.78e-15` |
| 本次 Gazebo 实际扫描的离线全局搜索对比 | 两版本均成功，最大数值差 `2.00e-15` |
| 本次 Gazebo 原始前端扫描重放对比 | 86 帧输入、两版本均接受 65 帧，全部输出逐值相同 |

独立 Gazebo `p13_yaw3` 单次正确性试验完成标定、自转、准备及三帧停车确认；三维位置误差约 **0.764 mm**，SO(3) 姿态误差约 **0.0299°**，通过原有 `0.10 m / 2°` 标准。定位器没有读取 GT；GT 仅由独立评分器使用。

同一新仿真环境中又使用原分支未修改的节点独立运行一轮，也通过正确性评分（约 **2.453 mm / 0.0279°**）。两版本停车及确认的墙钟耗时均约 **1.75 秒**，与当前仿真实时率相符。

这一试验保留目标分支的 192 线雷达和场地；未引入来源分支其他导航修改中的 288 线雷达设置。当前 CAD 仿真的实时率低于 1，本次开始到输出的墙钟时间超过历史 1 秒目标。数值一致性与单点正确性通过，不应将其写成完整 120 项性能批测通过，或保证新仿真的墙钟时延与旧仿真相同。

## 已有基线失败

`launch_bringup` 的原有导航/地图/碰撞配置测试共有 **17 项失败、41 项通过**。在未合并的独立 `735ef9a` 工作树上运行相同测试，失败项集合完全相同，没有新增失败。此次保留目标分支的参数和模型，因此没有为修复这些旧断言修改导航实现或测试期望。
