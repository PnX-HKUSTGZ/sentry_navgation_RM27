# PGM 通行权重：实现与验证（2026-10-31）

> 后续复核已发现并修复逻辑漏洞和仿真车高配置问题。最新结论见 [复核记录](prior_traversability_weight_audit_2026-10-31.md)：北侧回程和实体箱体测试仍失败，不能把下面的首轮测试当作完整验收。当前工作区仿真权重为 1.0，实车为 0.5。

首轮修改完成了共享 ROGMap／MINCO 逻辑和实车、仿真配置更新，当时两套配置权重均为 **0.5**。以下保留首轮设计和历史记录，当前配置及修复结果以后续复核为准。仿真对照发现：当前观测稀疏程度下，0.5 仍会明显降速；权重 1 才能取消完全无观测白区的地形完整性要求。不能把权重功能完成等同于默认 0.5 已解决全部慢行和短停。

## 配置与使用

实车：`src/pnx-launch/launch_bringup/config/reality/minco_params.yaml`。

仿真：`src/pnx-launch/launch_bringup/config/simulation/minco_params.yaml`。

两者参数路径均为：

```yaml
planner_server:
  ros__parameters:
    MincoPlanner:
      rog_map:
        projection:
          prior_map:
            enable: true
            traversability_weight: 0.5
```

`enable` 仍控制先验地图加载；原 `free_fills_unknown` 已删除。旧参数仍出现在启动配置时会明确报迁移错误，避免默默使用另一套语义。权重必须为有限的浮点数且位于 `[0,1]`。

这是启动／配置阶段读取的参数。修改 YAML 后重新启动导航；复核修复后，运行时修改会明确拒绝，避免参数值与内部策略不一致。可用下面的命令核对加载值，启动日志也打印权重：

```bash
ros2 param get /planner_server MincoPlanner.rog_map.projection.prior_map.traversability_weight
```

## 决策规则

已知 PGM 白区内，每一项证据分数都必须达到 `1 - traversability_weight`，三项不能相互平均抵消：

| 权重 | 每项实时证据要求 | 行为 |
| --- | --- | --- |
| 0 | 1.0 | 不使用白区放行证据，保留 PGM 黑区、边界与全局规划 |
| 0.5 | 0.5 | 每项至少有一半证据，不会无条件放行完全盲区 |
| 1 | 0.0 | 白区不再要求地面／净空／坡面观测完整，实际障碍仍阻挡 |

非白区的有效权重为 0。PGM 黑区、边界／无效地图变换仍有独立阻挡；三维屋顶净空证明也不再覆盖 PGM 黑格。

实际证据的实现口径：

- **地面支撑／连通**：独立连到机器人地面的实测表面为 1；仅有当前薄地面候选为 0.5；缺少本格地面时，每个兼容且独立连通的邻近地面样本贡献 0.25，上限 0.5。原有局部屋顶复核获得的独立地面参考也可提供完整支撑。
- **净空覆盖**：本格已知车体高度区间比例除以原严格比例阈值，再受观测数量完整程度约束，限制在 `[0,1]`。邻近严格净空通过的实测列只提供最高 0.5 的部分覆盖证据，不能冒充本格完整观测。
- **坡面连续性**：独立地面连通通过为 1；否则按兼容高度／坡度的实测邻居数与 `ground_connectivity_quantile_min_samples` 的比值计算，上限 1。

邻域半径为 `max(地图分辨率, min(overhead_ground_search_radius, ground_connectivity_quantile_lateral_radius))`。邻域证据只取实际候选和独立连通结果，放行后的格子不能反过来制造新的证据或无限延伸放行区域。

当前车体覆盖范围存在自遮挡时，有效车体姿态与当前占据／接地关系可提供三项各 0.5 的部分物理证据，但仅限零占用回波的当前足迹，不沿运动方向外推，不留下自由轨迹，权重 0 时不能因此放行。这与原先不受权重约束的近场白区填充不同。

## 实时障碍优先

低净空、墙体、无法解释的占用回波及不兼容的抬高表面保留独立硬阻挡。`HEADROOM_BLOCKED` 不作统一放行；厚回波只有先经过原有局部地面复核，证明是可通行屋顶，才能解除相应阻挡。

占用回波不再因总观测数量不足而先变成 UNKNOWN。权重策略启用时，不使用旧的白区多帧障碍确认豁免；已观测障碍首次更新即阻挡，原有障碍消退保持仍生效。形态去噪不能擦除这些硬阻挡。

旧的白区 UNKNOWN 填充、独立近场填充、规划器 `allow_unknown_motion` 白区净空豁免已退出这条决策路径。规划器不能通过未知区域开关或动态边缘容差绕过未满足权重要求的格子。地图变换／滚动窗口更新时，白区证据会独立刷新；不依赖该列恰好又收到新雷达数据。

新增查询诊断包含 `prior_traversability_weight`、`ground_evidence`、`clearance_evidence`、`slope_evidence`、`terrain_policy_active`、`terrain_admissible`、`prior_assisted`、`hard_obstacle`。阻挡日志会输出权重、三项分数、是否放行及是否硬障碍；先验辅助放行使用 `PRIOR_ASSISTED_CLEARANCE`，不会把它标记为完整雷达证明。

## 首轮验证结果与实际限制（复核前历史记录）

构建：`rog_map`、`minco_planner`、`launch_bringup` 均通过。

回归：ROGMap 160 个、MINCO 143 个 GTest 用例全部通过。覆盖权重端点与中间值、逐项证据、非白区、完全盲区、邻域不传播、当前足迹不留下自由轨迹、坡面、移动障碍首帧阻挡、障碍保持、地图变换撤销白区、旧参数拒绝、实车与仿真实际配置加载，以及规划器未知／边缘容差／过期地图不能旁路。

以下速度来自独立 Gazebo 真值里程计，按仿真时间计算，包含起停。未改变 1 倍仿真设置。

| 测试 | 权重 | 到达情况 | 路程／时间平均速度 | ≥0.4 秒停顿 |
| --- | --- | --- | --- | --- |
| 西侧三段平地，云台收起 | 0.5 | 2/3；第一段 35 秒超时 | 0.261 m/s | 0；但持续低速 |
| 同三段平地，云台收起 | 1.0 | 3/3 | 1.220 m/s | 0 |
| 同三段平地，云台持续转动 | 1.0 | 3/3 | 1.201 m/s | 0 |
| 北侧上下坡／过洞往返 | 1.0 | 2/2 | 0.982 m/s | 4 次，0.42～1.20 秒 |

0.5 平地首段慢行日志出现白区三项证据为零的前向格子。按约定的逐项证据门槛，这些格子必须阻挡，不能只凭白区就伪造 0.5 的实时证据。需要当前盲区内仍快速前进时，选择 1.0 才符合该语义；本次仓库中的两套默认值仍保留用户指定的 0.5。

北侧权重 1 仍有净空阻挡判定，例如 `HEADROOM_BLOCKED`、局部估计净空 0.021～0.038 m。日志能证明算法仍在阻挡该回波，不能单凭这个标签就证明现场存在实体障碍，也不能直接判为误报；本次没有取消这类占用几何约束。因此不能宣称所有过洞短停已消除。

障碍回归使用受控的占用体素序列，验证已进入地图的移动障碍不会被先验覆盖。没有实车测试，也没有据此宣称完整实体动态障碍感知与绕行验证完成。此前独立插箱实验曾出现原始雷达缺少箱体回波的现象；本权重修改不能补出传感器没有返回的数据。

汇总数据见 `docs/validation/prior_traversability_weight_2026-10-31.json`，其中保留每段速度、停顿及原始测试报告路径。所有权重 1 测试均使用 `/tmp` 下的配置副本，未更改实车／仿真默认权重。
