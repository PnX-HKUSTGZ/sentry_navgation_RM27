# 2026-10-28 夜间横向摆动修复

## 用户运行与复现

检查了 `~/.ros/log/2026-10-28-23-03-56-221557-powercenter-1607086/` 及其节点日志。
用户目标为从约 `(-9.55,-0.03)` 到 `(5.32,-1.28)`，在约 22 秒后收到退出信号；
退出时的 DEACTIVATED/取消记录不当作运行故障。日志记录洞前局部路径拒绝、刹停及重新规划，
但没有连续轨迹/速度录包，不能仅凭该日志定量还原摆动。

本轮在相同出生点和目标复现，随后反向导航至 `(-9.45,2.76)`，增加双向穿洞检查。
一直使用 Point-LIO 在线定位，保留全局初始化与静止 GICP；Gazebo 真值只供独立观察程序评价。

## 发现和修复

1. 20 Hz 控制器使用 10 Hz 前端的位姿。复现中里程计年龄中位数约 145–165 ms，95 分位
   205–225 ms。原代码补偿固定 120 ms 的底盘响应，却没有将里程计从采集时刻推进到控制时刻。
   原始滞后位姿与当前真值的 XY 距离不能当作定位漂移；第一段该距离的 95 分位为 22.0 cm，
   用里程计自身速度推算至当前时刻后为 4.6 cm。这是离线验证，不是在线使用真值。
2. 增加 `compensate_odometry_age`，默认关闭，在仿真 MINCO 配置启用。仅在正常行驶且速度
   超过已有静止门槛时，以已转换到世界坐标的速度外推状态，然后选择空间参考点，再进行原有
   底盘响应补偿。外推不改变消息时间戳、TF 或定位输出；不延长 250 ms 里程计新鲜度限制。
   小幅未来时间偏差只按零外推处理，超限/非有限输入仍停止。停车起步、制动和脱困保留原契约。
3. 时间对齐单独试验降低了跟踪误差，但没有降低反复纠偏次数，因此不能把这一项当作完整解决。
   仿真 MPC 同时调整 `q_cross: 60 → 12`、`R: [1.5,1.5,1] → [3,3,1]`、
   `control_delta_weight: [6,6,0.5] → [12,12,0.5]`，减轻横向误差放大，增加对平滑速度参考的
   跟踪及相邻指令连续性。速度、加速度、车身模型、净空门槛和障碍检查未放宽。
4. 轨迹对照发现，SMAC 栅格路线在部分开阔区域也有米级长段波折，原逐点曲率平滑只圆滑了
   局部拐角。新增 `path_smoothing.enable_shortcuts`（默认关闭，仿真开启），先对长短不同的
   点列尝试拉直，再细化曲率。保留点数、端点和高度；所有点仍受原路线 0.25 m 偏移上限约束，
   每条新边逐栅格/车身检查，峰值与均值代价始终相对原边，不能通过重复优化累积放宽。
   取消时恢复原路线；未知或无效原边不能被捷径跨过。原碰撞检查与 10 ms 协作式平滑预算继续生效。
5. 观察工具保存完整规划参考、里程计速度/姿态以及 MPC 和最终底盘指令，方便区分规划绕行、
   控制误差及定位时间差。全局引导线自身的部分弯折属于绕障，不能把所有横向运动都计为控制振荡。

实车参数未调整，新增外推功能在实车仍默认关闭。没有增加外部指令低通滤波器或连续重定位后端。

## 验证方法

测量参考为 Gazebo 实际轨迹与当时生效的全局引导线的有符号最短横向距离。统计只包含
速度超过 0.15 m/s 且距终点超过 0.35 m 的样本；跨引导线次数使用 ±1.5 cm 滞回门槛，
全局换路或采样间断时重置计数。误差和累计横向变化也包含拐弯/绕障，属于跟踪与运动变化指标，
不等于纯振荡幅度。洞区穿越要求实际跨越洞两侧，不能仅用 action 成功判断过洞。

证据位于 `tools/global_relocalization/.build/lateral_sway_fix_20261028/`，包括原运行日志副本、
每轮启动/观察输出、实际运行参数、输入时间审计、完整参考、采样轨迹及 `comparison.json`。
保留了 `baseline`、只补偿时间的 `age_1`、中间增益 `damped_1` 与较低增益 `damped_low_1`。
`release_*` 仅含控制器修复，之后发现的全局长波折尚未处理；最终组合版本使用 `final_*` 标签，
不把前一阶段的最好结果冒充最终版本结果。

控制器 6 个、规划器 12 个 CTest 套件通过。规划器新增长波折拉直、薄障碍/未知/软代价、
车身包络、取消回滚和高度保持测试。新增测试覆盖时间戳外推、未来偏差、过期和非有限输入，
10 Hz 延迟观测/20 Hz 控制/130 ms 执行器模型的横向超调，以及开启补偿后的匀速参考、制动和脱困。
动态单测将 8 cm 初始偏差后的最大反向超调由约 10.5 mm 降至 0.24 mm；该模型用于回归，
不能替代实际 Gazebo 复跑。上轮记录的完整启动配置套件 10 项遗留失败未在本轮修改。

## 最终默认入口结果

`final_1` 与 `final_gui` 均从 `(-9.55,-0.03,0)` 出发，依次到 `(5.32,-1.28)`、
`(-9.45,2.76)`；两段都选择南侧通道。`final_tunnels` 使用另一条原有基准路线：
`(-9.145,-0.295,0)` → `(9.74,0.79)` → `(-9.45,2.76)`，分别验证南、北洞。
最终六段全部 action 成功且实际穿洞，没有超时，默认配置实际参数已从节点读取核对。

用户同款路线第一段的横向加速度 RMS 从 0.910 降至 0.520 / 0.556 m/s²；
累计引导线横向误差变化从 2.89 降至 0.99 / 0.93 m。初始开阔区的引导线不再反复交替改变方向。
回程 RMS 没有在每次试验都下降，主要改善是反复纠偏次数、累计偏移变化和完成时间；
不能把第一段的改善比例推广到所有路段。

最终六段到达真值误差范围为 8.9–13.1 cm，保留原目标容差。
无界面同款路线两段没有 ≥0.1 s 的短停；带界面第一段有一次 0.36 s 短停。
另外的南/北洞补测中，南洞仍有 0.42、0.12、0.24、1.38 s 的短停，日志对应
`OVERHEAD_GROUND_UNVERIFIED` / `GROUND_UNVERIFIED` / `HEADROOM_BLOCKED` 等净空与地面证据等待；
北洞没有该类短停。因此本轮确认横向反复修正改善，**不宣称所有过洞犹豫消失或每次穿洞都更快**。
该剩余现象未通过放宽车高/未知区域策略掩盖。

## 启动

结束旧导航后从工作区根目录启动：

```bash
bash tools/global_relocalization/navigate.bash world:=RMUC2026 use_ground_truth_odom:=false
```

默认开启 Gazebo/RViz，仍可使用 RViz 选择初始位置和发送目标。现有 `ros2 launch` 入口同样读取
本次修改后的仿真配置；需先 source 当前工作区环境。
